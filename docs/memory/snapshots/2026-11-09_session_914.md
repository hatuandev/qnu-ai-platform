# Context914 — Quy trình xử lý ngược cho QNU V1

- Nhánh `feat/v1-user-workflow`, mốc `7c1cef65`. Batch backend + hợp đồng API cho bốn thao tác
  ngược: Dừng xử lý, Ngừng dùng cho trợ lý, Cập nhật tài liệu, Xóa vĩnh viễn.
- Revision mới mặc định `staged=true` (ứng viên), summary trả ba bản serving + `actions` +
  `preparation`; replace giữ bản cũ đến khi index mới sẵn sàng.
- Cancel/link `CompilationRun` dùng fencing + khóa `prep:<intent_id>`, lease 180 giây; reconcile
  không làm sống lại lượt dừng; kết quả không xác định ghi `uncertain`.
- Withdraw ẩn ngay khỏi RAG/dẫn chứng, bản cuối retire generation và `kb_index_sync.status=empty`.
  Purge một preview + một xác nhận, tự thu hồi, checkpoint/lease 120 giây, takeover admin có audit,
  tiếp tục trên cùng biên nhận sau lỗi.
- Khôi phục thư mục kiểm kho/cha/tên; xóa model còn tham chiếu trả `409 model_provider_in_use`;
  migration mới `0020_reverse_flow`.
- Focus groups đạt: 72 ca chuẩn bị/phát hành/index/provider/capacity/auto-extraction; 8 ca dừng an
  toàn; 8 ca purge; 15 ca summary/thư mục; 3 ca replace-withdraw/xóa model. Full suite kết quả ghi
  trong nhật ký.
- Chưa áp migration lên DB ứng dụng, chưa restart/reindex, chưa commit/push; F13 và lỗi nền RAG
  vẫn là việc riêng.
