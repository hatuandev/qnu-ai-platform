# Session695 — ModelOps pool, pre-dispatch fallback và registry

Người dùng yêu cầu mục3–5 từ nghiên cứu9router; triển khai trong backendV1 và
frontendV1. Chính sách opt-in trong DB, không migration/dependency/.env mới.

- Pool: PostgreSQL provider → key, UUID fencing và TTL, dùng lease/cooldown/
  failure columns cũ.401/429 mới đổi khóa cùng target, max3và chung deadline;
  gateway owner chỉ1, dương usage/uncertain/cancel không retry. Revoke/rotate
  giữ đúng lock order. Anonymous OCR không lặp lại khi không có khóa khác.
- Routing: flat chain theo task ở provider mặc định, trước pin/budget/ledger;
  explicit provider là hard pin, grant/capability/transport/capacity/quota giữ
  nguyên. Embedding không đổi model; OCR/Compiler giữ target giữa run.
- Protected execution scope mang factory DB người gọi và usage_id; restore
  không đọc khóa/ledger từ DB gốc. Attempt audit an toàn có model/latency/
  status/token unknown, link usage; FE có form policy và lịch sử.
- Registry API dùng chung FE, phân biệt hợp đồng adapter với kiểm chứng model;
  Responses/tools/streaming/Gemini/PaddleOCR runtime chưa có, fail closed.
- Diagnostic identity không dùng updated_at lease/cooldown nữa; history trước
  nâng cấp có thể stale một lần. Không tự chạy lại model, đổi default/grant/
  quota/keys thật hoặc restart người dùng.

full FE400PASS, scoped Ruff44/Biome10/build+TS PASS, browser desktop/mobile
sáng/tối và draft isolation đã kiểm. Replay lock order cũ2FAIL có chủ đích rồi
current regression PASS. FE đầu có1timeout, lượt4worker đạt; không sửa test nền.
