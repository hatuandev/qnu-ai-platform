# Admin Starter Core — Agent Rules

## Non-negotiable architecture

- React + TypeScript + Vite.
- TanStack Router, Query, Table, Form + Zod.
- shadcn/ui-style source components backed by Radix primitives.
- Tailwind CSS 4 is the only styling engine.
- `src/styles/tokens.css` is the source of truth for semantic visual tokens.

## Design-system rules

1. Do not introduce another UI library (Mantine, MUI, AntD, Bootstrap, etc.).
2. Do not create a replacement for an existing shared primitive.
3. If shadcn has the primitive, prefer `npx shadcn@latest add <component>` and merge deliberately.
4. Never hand-roll keyboard/focus/portal behavior already handled by Radix.
5. Do not globally style `button`, `a`, `input`, `select`, `table`, etc.
6. Do not hard-code feature colors; use semantic tokens (`bg-success`, `bg-info`, `bg-warning`, `text-success`, etc.). Never use raw Tailwind palette classes (`emerald-500`, `blue-500`, `amber-600`, etc.).
7. `components/ui` owns low-level primitives only.
8. `components/admin` owns reusable admin compositions.
9. `features` owns domain-specific composition and state.
10. Routes orchestrate; route files should stay thin.
11. Any design-system change must be checked on `/design-system`, `/users`, desktop/mobile and light/dark.
12. Body, navigation and default controls MUST be 14px.
13. Compact toolbar controls (search inputs, filter selects, toolbar action buttons) use 12px (`text-xs`) with `size="sm"` for density.
14. Table body is 14px on desktop (`sm:text-sm`) and 12px on mobile (`text-xs`).
15. Table headers are 12px (`text-xs`), semibold, muted-foreground.
16. 12px is reserved for secondary, meta, caption and compact-toolbar content.
17. 11px is reserved for group headings, eyebrows and microcopy.
18. 10px is reserved for keyboard shortcuts or exceptional micro labels.
19. Do not shrink standard UI text to make a layout fit; fix the layout instead.

## Navigation

- One source: `src/navigation/config.ts`.
- Sidebar, command menu, breadcrumbs and RBAC derive from that source.
- Support at most two navigation levels: parent → child.

## State

- Server state → TanStack Query.
- URL state → TanStack Router search params.
- Form state → TanStack Form.
- Local interaction state → React state.
- Do not add Zustand/Redux without a concrete cross-feature requirement.

## Validation

Run after meaningful changes:

```bash
npm run typecheck
npm run lint
npm run build
```

`src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin and must not be edited manually.

## Final design system rules

- Default control radius is 6px; default surface radius is 8px.
- Feature list/table cards and workflow summary panels use `rounded-xl` with `shadow-2xs` as the elevated surface style.
- Inputs and controls inside dialogs keep the standard 6px radius and no decorative shadow.
- Controls, navigation and body text remain 14px; compact toolbars and table headers use 12px.
- Use shared Textarea, Tabs, RadioGroup, Alert, Progress, EmptyState and Field compositions instead of raw custom primitives.
- Do not add a new UI library or arbitrary design-system component without a real use case.

## Compact toolbar pattern

- List-page toolbars use a compact density: search input `text-xs`, filter selects `text-xs` with fixed widths (`sm:w-40`–`sm:w-60`), action buttons `size="sm"` with `text-xs` and `size-3.5` icons.
- Toolbar wraps to a full-width column on mobile (`flex-col w-full sm:flex-row sm:w-auto`).
- Keep the same compact toolbar contract across all list pages (assignments, invoices, students, applications, etc.).

## Dialog pattern

- Form/action dialogs use the structured layout: `ResponsiveDialogContent` with `p-0 gap-0`, scrollable body (`min-h-0 flex-1 overflow-y-auto`), bordered header (`border-b bg-muted/20`) and bordered footer (`border-t bg-card`).
- Dialog titles pair an icon tile (`size-8 rounded-lg bg-muted`) with the title text; descriptions are `text-xs text-muted-foreground`.
- Dialog footers use a 2-column grid on mobile and a right-aligned row on desktop.
- Max height is capped at `max-h-[min(820px,calc(100vh-2rem))]`.

## Workflow summary pattern

- Workflow/status summary panels use a 2-panel grid (`lg:grid-cols-12`, left 7 / right 5) with `divide-x` on desktop.
- Capacity/progress bars are stacked segments using semantic tokens (`bg-success` for finalized, `bg-info` for pending).
- KPI mini-cards use a 2x2 grid with `text-[11px]` labels, `text-xl` mono values and `text-[11px]` hints.
- Status dots inside badges use semantic tokens (`bg-success`, `bg-info`, `bg-warning`, `bg-muted-foreground/60`).

## Motion rules

- Motion must be functional, not decorative.
- Use the FAST (140ms), BASE (180ms) and SLOW (240ms) timing contract.
- Sheet uses a spatial slide from its opening edge; Dialog uses subtle fade/scale.
- Dropdown and Popover use subtle fade/zoom/directional motion; Select and Tooltip align with the same language.
- Do not use standard UI animations longer than 300ms, bounce/spring motion or animation libraries without an explicit requirement.
- Do not add route transitions or stagger table rows.
- Respect `prefers-reduced-motion` globally and keep Radix state/focus behavior as the source of truth.

## Table pagination rules

- `DataTablePagination` is compact by default: 12px text, 32px (size-8) page buttons, no border.
- Use the `bordered` prop only when the pagination sits outside a table card and needs its own surface.
- Pass `total` to show the record count inside the pagination bar; do not render a separate "Tổng cộng" line below it.
- Do not re-add the old bordered/full-size pagination style; keep all tables on the same compact contract.
- `DrawerFooter` is a single-row, right-aligned footer; do not restore `flex-col-reverse` or backdrop blur.

## Extended component rules

- Date display defaults to `dd/MM/yyyy`; never parse that display format with `new Date(string)`.
- Use `src/lib/date-utils.ts` for date parsing/formatting and keep presentation separate from storage semantics.
- Use the shared React DayPicker-based Calendar for DatePicker compositions; do not hand-build calendar grids.
- Use Combobox for searchable/large option sets and Select for small option sets.
- Use Drawer primarily for mobile/bottom temporary surfaces; do not replace Sheet blindly.
- FileUpload must preserve native file-input accessibility, validate only for client UX and never fake upload progress or call a server.
- Check the existing dependency tree before adding date/upload libraries; keep the project Radix-based.
